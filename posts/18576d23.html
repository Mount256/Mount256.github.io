中途紧急切换分支修bug

发表于2026-06-12|更新于2026-06-12|Git
|总字数:918|阅读时长:3分钟|浏览量:

这是 Git 多人协作中最经典的「中途紧急切分支修bug」场景，核心解决方案是用 git stash 临时保存未完成的工作，完整操作流程如下（按顺序执行）：

✅ 标准解决方案（推荐，无脏提交）

🔹 第一步：临时保存当前dev分支未完成的工作

你现在在dev分支，代码写了一半不想提交，用 git stash 把所有修改临时"藏起来"，让工作区恢复干净：

✅ 验证：执行 git status 会显示工作区干净，没有未提交的修改了。

🔹 第二步：创建bug修复分支（⚠️ 关键：从干净的主分支拉，不要从dev拉！）

绝对不要从当前的dev分支创建bug分支——dev分支有未上线的开发代码，会把未完成的代码带到bug修复分支里！

🔹 第三步：修复bug，完成提交合并

PR评审通过合并到主分支后，bug修复流程完成。

🔹 第四步：回到dev分支，恢复之前未完成的工作

✅ 执行完后，你之前写了一半的代码会完整恢复，继续开发即可！

2. 恢复stash时出现冲突怎么办？

如果恢复的时候，dev分支的代码和stash的代码有冲突，Git会提示冲突，和解决合并冲突一样：

  • 手动修改冲突文件
  • git add 冲突文件 标记解决
  • 不需要commit，冲突解决完就可以继续开发了

📌 备选方案（不想用stash的情况）

✅ 效果和stash一样，缺点是会多一条临时的脏提交，不如stash干净。

⚠️ 新手最容易踩的坑

❌ 错误做法：直接从dev分支创建issue-101分支
→ 会把dev里未上线的开发代码带到bug分支，合并到主分支后会把未完成的代码也带上，造成线上事故！
✅ 正确做法：所有hotfix/bugfix分支，必须从干净的线上主分支（main/master）创建！
